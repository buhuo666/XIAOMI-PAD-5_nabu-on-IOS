# GPU226 early admission and the native minimum-duration path

2026-11-12, Asia/Shanghai. Read-only investigation; no production edits, device actions, or CI dispatches were performed by this analysis.

## Conclusion

GPU226's single-free-page retry already works. All 1800 measured App frames have a successful early `can_update(flags=1)` before the later update which selects that App sample. The early update emits only a `set=clear=2` empty layer-1 operation. Further widening page admission would attack the wrong boundary.

The exact 3.5 ms offset has an original-code explanation: ordinary `CAMetalDrawable present` supplies an implicit minimum duration of 4 ms; its common implementation subtracts 0.5 ms, and the image-queue consumer turns the resulting relative 3.5 ms into an absolute sample time based on a preceding consumed sample. The existing native `CAMetalLayer.lowLatency` property selects the zero-duration branch of ordinary present. It is the smallest existing path to test with GPU225 admission plus GPU226 no-rescan clear handoff. This is a candidate, not a claim of achieved latency.

## Runtime evidence and its limits

`gpu226-admission.json` is generated by `extract.py` from the recorded `log/host/gpu-v226/default-ca-analysis.json` and the complete measured-frame selection in `default-ca-path.json`.

- 1800/1800 frames contain an early successful flags-1 call. Mean early success to the begin of the update which actually selects that frame: 4739.924 us.
- First measured frame is App epoch/index `4294967649`, surface 20. Present returns at 134918868 us. The flags-0 call returns false at 134919144 us; flags-1 returns true at 134919183 us.
- CA update 2401 begins at 134919405 us and finishes through swap 982. Its request contains surface IDs `[0,0,0,0]`, set 2, clear 2. Its update48/update68 target is 134.91907109375 s.
- The later CA update 2402 begins at 134923916 us and submits surface 20 as swap 983. Its target is 134.9315340625 s. Its selected sample carries sample time 134.92669640625 s.
- Thus the observed later sample time exceeds the early target by 7.6253125 ms. The trace agent's independent all-frame analysis in `log/host/gpu-v226/phase-evidence.json` finds a mean 7.637260 ms and a mean 3.500503 ms offset after the first physical VBlank reachable from submission.

The early update has **no recorded queue snapshot**. The sample timestamp above is observed in the later update, after CA has had an opportunity to resolve a relative timestamp. It is not a direct observation of the sample's raw bytes during the early update. Static data flow plus this exact runtime offset supports the minimum-duration diagnosis; GPU227 must still verify the zero-duration property path and its actual selected sample.

## Page indices and original admission

- `0x188235f54` (`can_update_`), `0x188236020..070`: `+0x360` is page count, `+0x358` is next page to prepare, `+0x35c` is the most recently committed page. It examines at most two pages starting with next, wrapping by count, and normally skips the current page.
- `0x1882360d4..1f4` cleans only pages whose recorded swap has really retired, then releases their original references/fences. This must be preserved.
- `0x18823627c..2e4` and `0x18823639c..3d4`: flags bit 0 permits an already found free page to remain sufficient when a later page is busy; it does not fake SwapWait success.
- `0x188264980..994` (`finish_update_` tail helper): stores next into current, increments next, wraps it to zero at count. It rotates all three pages; GPU226's early updates consume the third page as a logical clear transaction.
- `0x188324660..680` constructor establishes next 1/count 3 on the normal path.

These anchors are in the pre-existing `analysis/framebench-drawable-20f66/188235f54.asm`, `18826491c.asm`, and `188323eb0.asm`. No changes to count, current/next indices, resource retirement, or held surfaces are warranted by this evidence.

## The implicit 4 ms / relative 3.5 ms path

1. Ordinary `-[CAMetalDrawable present]`, `0x1882a074c..76c`, derives a private bit10 gate from `_CAMetalLayerPrivate+0x108`: bit10 is allowed only when bit0 (lowLatency), bit3 (presentsWithTransaction), and bit9 are all clear.
2. At `0x1882a095c..998`, when bit10 is set and the separate global at `0x1e1b9cdf5` is false, the method sets argument flags bit1 and supplies `double 0.004` (`0x3f70624dd2f1a9fc`, original constant at `0x1884d40f8`). Otherwise it supplies zero.
3. `layer_private_present_impl`, `0x188214d28..44`, compares duration to `0.0005` and subtracts `0.0005` on the positive-duration branch. The implicit 0.004 becomes 0.0035.
4. `0x188214ed8..ef0` maps the argument's minimum-duration bit1 into image flags bit31. `0x188214fcc..fe0` forwards the double and flags to `_CAImageQueueInsertImage_`.
5. `_CAImageQueueInsertImage_`, `0x188270b10..20`, enables queue bit28 for relative-duration entries; `0x188270be8..bfc` stores flags at sample+0x48 and the relative duration at sample+0.
6. `CAShmemImageQueueCopyImageInfo`, `0x188278fe4..279048`, processes queue bit28, finds the latest qualifying consumed entry by insertion seed, and derives the base from `max(sample+0, sample+0x10)`.
7. `0x1882790ac..c4` identifies the next relative entry. `0x188279a40..a64` adds that base to the stored duration unless the separate absolute-time marker bit26 is set. It then clears bit26 and bit31 (`0x188279a68..a84`). Consequently a later snapshot can show an ordinary absolute time and no remaining relative flag.
8. Subsequent time-based selection compares sample time against input target at `0x1882794c0..4d0` and maintains candidates on the appropriate side of the target. This is real selection policy, not an IPC delay or GPU fence wait.

Original assembly for steps 1–4 is under `analysis/cametal-20f66-v173/`; step 5 is newly retained here as `188270a30.asm`; steps 6–8 are in `analysis/framebench-drawable-20f66/188278e44.asm`.

## Existing native zero-duration control

The property is not merely a getter label:

- `-[CAMetalLayer setLowLatency:]` (`0x18831e26c`) uses the original Layer setter for atom `lowLatency`.
- `-[CAMetalLayer didChangeValueForKey:]`, `0x188214230..25c`, compares the `lowLatency` key, reads the original getter, writes its result into private+0x108 bit0, and rejoins the original superclass notification path.
- `CAMetalLayer init`, `0x1882238e4..8f8`, initializes the same bit0 from the getter.
- Ordinary present then follows the zero-duration branch above. The existing FrameBench calls setLowLatency before its run and records the actual getter value.

Use the existing 15-second native-lowLatency test first. Keep GPU226's resources, actual completion/retirement, three drawables, and hardware scan boundaries. Check actual lowLatency readback, fresh run/epoch, all measured frame identities, real pixel accepts, failures, and the sample timestamps. A property readback or improved submission rate alone is insufficient.

## Native defaults/environment and propagation scope

`flag-candidates.json` retains the bounded string/data/ADRP scan. The original `init_debug` loop (`0x1882f0a90..ac4`) maps 153 string pointers from `0x1d57ff720` to boolean bytes starting at `0x1e1b9cd70`. `CADefaultsGetInt` (`0x1882f6a60..94`) first checks the named environment variable and converts its value; absent environment falls back to a CoreAnimation preferences dictionary/default.

- Index 133, string pointer `0x1d57ffb48`, is **CA_DISABLE_FIFO_IMAGE_QUEUES**, mapping to `0x1e1b9cdf5`. It makes ordinary present choose zero duration, but is also read by explicit `presentAtTime:` and `presentAfterMinimumDuration:`. Do not adopt it globally merely to remove 4 ms; it changes FIFO policy and needs separate scope/semantic review.
- Index 37 is **CA_DISABLE_LOW_LATENCY**, mapping to `0x1e1b9cd95`. This disables a native low-latency path; it is not a switch that enables default lowLatency.
- `CA_MINIMUM_FRAME_DURATION` is present in a separate numeric option table at `0x1d57ffd48`. It is not the constant controlling ordinary present's fixed 4 ms branch. No claim is made here that zeroing this option removes the observed delay.
- The bounded boolean table contains no identified environment setting which simply changes the default `CAMetalLayer.lowLatency` property to true. The verified API/property is the clear selective control. `+[CAMetalLayer defaultValueForKey:]` could be investigated for eventual defaults integration after runtime success.

Preserve caller-specified `presentAtTime:` timestamps and positive `presentAfterMinimumDuration:` constraints. They share `layer_private_present_impl`, so changing that common subtraction or all image-queue relative timestamps would broaden behavior beyond ordinary unscheduled present. Selecting the normal native property is more reviewable than overwriting private fields or timestamps.
