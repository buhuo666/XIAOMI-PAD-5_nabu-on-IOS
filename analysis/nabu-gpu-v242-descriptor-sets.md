# GPU242：普通描述符集只记录一次

2026-11-13。目标仍是 iPadOS 全程 120Hz/实际新画面供给，尚未完成。

GPU241 的 463 个精确关联提交包含 22,602,431 条原始资源范围，最终唯一范围为
506,956 条，约 44.6 倍。资源收集平均 0.937ms，其中最终去重 0.693ms。

源码中的 `tu_cmd_use_descriptor_set` 在每次普通描述符集绑定时追加同一个指针。
`tu_darwin_submit_add_resources` 随后对每个指针整表复制 `set->resources`。
同一个普通 set 只需要在该命令缓冲的资源清单出现一次，提交时仍读取其当前资源表。

候选通过扫描已有唯一指针，跳过重复追加；不增加索引分配或新的资源生命周期。
Push 描述符继续逐次记录当时的资源，更新后绑定标志仍执行原有处理。
现有 GPU232 的最终范围去重保留。

主机使用实际函数的修改前后版本比较：普通重复绑定、提交前资源更新、push 快照、
fallback 标志、命令缓冲重置均通过。

合成场景（8 个普通 set，384 次绑定，每个 set 128 条资源）中：

- set 引用从 384 个减少到 8 个；
- 连同未改动的基础范围，展开记录从 49,536 条减少到 1,408 条；
- 全部 128 次绑定均为不同 set 时，展开记录保持 2,176 条，额外指针扫描约 2.2µs。

这些是主机合成数据，不是 iPadOS 提升结果。完整 iOS Turnip 编译及实机收益待完成。
候选只重编 Turnip，继续使用 v238 内核和已验证的 GPU232 前端/runtime。
未使用之前未完成的 `tu_resource_range_index.h` 方案。

## 实机结果：没有确认预期收益

用户确认 GPU242 桌面、触摸正常，完成 15 秒滑动。214,501 条内核记录零丢失，
自动保存并 ACK。DPU 接受 890 次、拒绝 0 次，最忙整秒 86 次；不能称稳定 86fps。

817 个输出关联的提交仍有 41,629,943 条原始范围、876,972 条唯一范围，约 47.47 倍。
collector 平均 0.892ms，最终去重 0.646ms，runtime 批次 CPU 2.342ms。
GPU236（无 Mesa CSV）原始/唯一约 57.44 倍，collector 0.839ms；GPU241 约 44.58 倍，
collector 0.937ms。手动负载不同，但本轮没有出现期望的大幅重复记录下降，
不能把普通 set 指针去重作为已证实的性能改善。

本轮全部精确 CA 事务的 render CPU 平均 8.561ms、中位 7.965ms；仅 817 个有
GPU writer 的事务为 9.299ms / 8.187ms。GPU CP→RB 平均 10.864ms、中位 8.284ms，
817 个中 398 个超过 8.333ms。CA begin→finish leave 平均 11.298ms。

证据目录 `log/host/gpu-v242/desktop-01/`。设备仍在 GPU242 iPadOS，持久化槽1
未回收。GPU243 只增加提交资源来源计数：CS、命令缓冲自身（含 push 快照）、
普通 descriptor set 和 IB。三条标记之和需对应既有 raw 总数，再决定下一处优化。
