# Boot diagnostics after the Test136 logo recovery

These changes improve evidence for a boot that reaches the Apple logo but has
not demonstrated a usable desktop. They do not change LS, Metal, PAUTH
compatibility, root installation or partition permissions.

- **0178:** console producers publish their byte position only after writing
  their whole range. A single nonwaiting lock protects RAM publication and
  bounded copies. Contention is counted as lost calls/bytes in `NABU LOGQ`.
  Background diagnostics use `nabu_log_record` to avoid per-character printf
  interleaving. Existing v2 storage layout and allowed partition stay intact.
  The logger retries a contended copy without advancing the committed header.
- **0179:** SMP3 keeps identities and CPU times for threads with no usable
  saved user state (`stv=0`). Its priority cap is 128 records per sample,
  frames retain an independent 24 KiB budget. `W` records report state bits,
  block hint, opaque wait event, continuation and wait result. The sampler
  makes one scheduler-lock attempt with balanced interrupt masking, then
  formats outside the lock; `ok=0` explicitly means capture failed. It never
  dereferences wait objects or calls debugger-only owner helpers.
- **0180:** an 8192-entry boottrace queue is drained in batches of at most
  256 events / approximately 5 ms, yielding at least one scheduler tick.
  Idle waits target 20 ms instead of the previous one-second/128-event cap.
  `BTQ` reports pending/high-water entries and output loss; `BTC` retains
  producer acceptance/drop counters. Formatting and I/O remain off producers.

`SMP3 Q` is version 2: `ok` counts successfully published T records, while
`nostate` and `noexec` describe attributes of enumerated threads and are not
disjoint from `ok`. Other record versions retain their fields, with new W/D
record types. T `stv=0` must not be interpreted as actual zero user registers.
The per-record bound is now 384 bytes since structured records bypass the
legacy console formatter; the bounded publication API accepts at most 512.

The existing `nabusmpfirst`, `nabusmpint`, `nabusmpcount` options are retained.
After the scheduled samples, E records completion and D waits at most five
seconds for the preceding byte position to become durable. `covered=1` covers
those earlier sampler bytes only: it does not claim all live producers stopped
or that D itself has already been synced. No shutdown/reboot is triggered.

CI runs its existing build checks with updated interface fixtures and adds
actual-source tests for concurrent publication/readers, contention accounting,
stale RAM rejection and the live wait helper's lock/interrupt discipline.
Kernel compilation remains on macOS. These host tests do not prove hardware
bootability, disk durability or a root cause for the desktop problem.

## Interpretation limits

This remains bounded diagnostic capture. LOGQ/BTQ/BTC/Q can report loss; a
zero RAM-overrun value alone cannot establish complete coverage. The disk
header still has its v2 checksum, not a full-payload checksum or dual headers.
User registers, CPU counters and wait state are acquired at different times.
The continuation is a code pointer, not a full kernel backtrace, and a wait
event is not automatically a lock owner or RPC peer. Normal idle threads may
have repeated stacks. A successful build is not a demonstrated desktop fix.
